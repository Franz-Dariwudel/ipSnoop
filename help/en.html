ipSnoop 1.5.4

The Categories menu contains 24 categories in five groups: Devices and wireless, Addressing and routing, Connections and protection, Monitoring and diagnostics, and System. Menu entries are displayed without icons. Former Advanced categories are directly accessible. Find a section filters category and group names; the top search still filters results. Category selection survives a language change.

ipSnoop reads local Linux network data. Neighbor and Wi-Fi lists use existing caches; this is not complete device discovery, packet capture or an active network scan. Virtual machines show guest data.

Help

Refresh reads current data. Adapters shows IP/MAC addresses; the selector below opens details. Search filters the display. Disconnected adapters can be hidden; unknown states remain visible. Settings controls language and interval (default: manual). The selected report mode determines export scope regardless of the search filter. Standard CSV includes selected kernel parameters; full diagnostic CSV retains every collected detail. Red values are unavailable or not reported. Zero is a valid value.

IPv4 auto usually means DHCP; IPv6 auto can also use router advertisements/SLAAC and does not prove DHCPv6. Link speed is not Internet speed. Missing maximum speed is not guessed. STALE is not an offline diagnosis. Permanent MAC, firmware, Wi-Fi and process details may be unavailable.

Python 3.10+, GTK 4.8+, python3-gi, gir1.2-gtk-4.0, iproute2. NetworkManager / ethtool.

Settings: config/settings.json. Logs: logs/errors.log. Starting the interface, --scan or --check clears this file and removes the two rotated files errors.log.1 and errors.log.2. New messages remain throughout the session, including refreshes and opening dialogs. --help and --version do not change the log. Additional languages: languages/<code>.json, a UTF-8 JSON object with string keys and values. New languages are detected when opening settings; missing texts fall back to English. A single language is selected automatically. Help: help/<code>.html, exclusively in the selected language. The installer records created files in installation.json. Removal deletes those files and empty owned directories; personal files created later are retained.

Additional network data

The category menu offers separate detail categories for adapter/DHCP details, DNS, policy routing, VLAN/bridges/virtual networks, firewall, TCP/IP counters, kernel parameters, QoS, Wi-Fi, Bluetooth and network namespaces. Technical field names come from Linux tools. Each row includes its source and query status. No entries reported is a successful empty result; Unavailable indicates missing data. IS201/IS202 identify missing tools or failed queries.

Adapters include packets, drops, carrier errors, collisions, multicast and Wake-on-LAN modes. Virtual link speed is not applicable. PCI fields and lspci IDs supplement model identification. ethtool reads offloads, ring sizes, coalescing and driver counters when supported. No settings are changed.

DHCP options come from NetworkManager. Server, lease duration/expiry, client ID and DUID appear only when reported. Missing lease times are not estimated. IPv6 auto can mean SLAAC. Address lifetimes, flags, prefixes and privacy/RA settings appear under adapter details. resolvectl reads DNSSEC, DNS-over-TLS, mDNS and LLMNR. A failed query does not mean DNS is disabled; System also shows effective resolv.conf lines.

Connections shows TCP/UDP sockets and peers. Services and connections include PID, user and executable where accessible. Processes may exit between queries. Firewall queries often require elevated privileges; ipSnoop never requests privileges automatically. Failure does not indicate whether ports are allowed or blocked. The effective user ID is displayed.

Neighbors include additional cache fields, local /etc/hosts names and vendor names from an existing local ieee-data, arp-scan or nmap OUI database. Locally administered MACs do not reliably identify a vendor. No OUI database is downloaded. Wi-Fi details are read when an interface exists. Bluetooth lists known controllers/devices without discovery. Accessible named namespaces are inspected; unnamed namespaces are not entered. Docker/Podman queries use local connections.

Manual connection tests

In Connection tests, enter an IP or hostname, select Ping, Name lookup or Trace route and click Run test. Only this action sends diagnostic traffic, independently of periodic refresh. Ping sends four packets; tracepath uses at most twelve hops. Each test times out after 20 seconds. Choose your own gateway, DNS or Internet target. Name lookup may use DNS/mDNS according to NSS configuration. Missing replies do not prove an outage. Results remain for this session and are included in CSV exports.

Optional packages: ethtool, pciutils (lspci), systemd-resolved (resolvectl), procps (sysctl), nftables, ufw, iw, bluez (bluetoothctl), iputils-ping and iputils-tracepath. bridge/tc belong to iproute2. Docker/Podman are queried only if installed. Missing tools do not prevent other queries; no packages are installed automatically.

IS204
Invalid target or test type. No test runs. Enter an IP address or hostname without spaces, options or IPv6 zone ID, then retry.

The toolbar uses 3D icons; the category menu uses text labels. The ipSnoop logo appears under Help → About.

Select a section in the Categories menu. Results use the full window width.

Category navigation and column headings remain visible while scrolling. Only data rows scroll vertically; horizontal scrolling keeps headings aligned with data.

TCP quality, NIC, LLDP, VPN and live data

TCP quality shows RTT, RTO, cwnd, retransmits and other socket data reported by ss -ti. Fields depend on the kernel and connection. Adapter details adds ethtool -l (channels), -x (RSS) and -T (timestamp capabilities). Unsupported queries do not indicate defective hardware.

LLDP reads known neighbors using lldpcli and an existing local LLDP daemon. ipSnoop starts neither a daemon nor discovery. Connection tracking reads conntrack -L/-S and kernel count/max. nftables rules include packet/byte counters where configured; absent counters are not invented. conntrack/nft/WireGuard may require privileges. IS201 means a missing tool; IS202 means a failed query, e.g. insufficient permissions or an unavailable service.

VPN detection uses active NetworkManager VPNs and tunnel types. TUN/PPP/XFRM interfaces are VPN candidates, not proof of an encrypted tunnel. WireGuard shows public keys, endpoints, latest handshakes and transfer counters. Private keys and configuration files are never read. An old handshake alone does not prove an outage.

Live data shows receive/transmit bytes/s, packets/s and errors/s. Local sysfs counters are sampled once per second using actual monotonic elapsed time. These are interval averages, not Internet speed tests. The initial sample, counter resets, device changes and pause/resume require a new baseline. The checkbox pauses sampling. Latest rates are included in CSV. General refresh and manual connection tests remain independent.

Additional optional packages: lldpd (lldpcli), conntrack and wireguard-tools (wg). Nothing is installed or enabled automatically.

Column headings and controls remain visible while scrolling in every section. Adapter overview and details scroll independently.

Known devices: names come from /etc/hosts first, then automatically from getent using system NSS configuration (DNS/mDNS where configured). This may send name queries, but does not discover additional devices. At most 16 addresses per refresh, four in parallel, with a 1.5-second timeout each. Successful names are cached for five minutes, unsuccessful results for one minute. Refresh again for larger lists. Without DNS PTR/mDNS records names remain unknown. Cache details show source/status; IS201/IS202/IS203 also apply to these queries.

Disconnected adapters are hidden by default; the checkbox shows them again. Unknown states remain visible. Missing packages appear above results with a copyable installation command; ipSnoop does not install them automatically. config/visibility.json stores the visibility option separately. For IS102 after a previous administrator session, start once as administrator to restore settings ownership to the configuration directory owner.

Status shows Administrator for effective user ID 0, otherwise Standard user. Administrator-rights hints in Services and Connections are omitted when already running as administrator. Actual query failures remain visible because tools, services or devices can still be unavailable.

Optional ethtool queries

The NIC detail queries -S, -k, -g, -c, -l, -x and -T depend on driver support. Responses stating “Operation not supported”, “Not supported” or “No data available” produce a neutral status instead of a red warning, without a new IS202 log entry. Missing tools, permission failures, timeouts and other errors remain visible and logged. The session log is reset at the next application start.

Reports and privacy in 1.5.4

Select Standard CSV, Full diagnostic CSV or Short report (TXT), then click Save report. Standard includes summary, scan timing, adapters, grouped neighbors, routes, sockets, live data, findings and query statuses, with only ten core kernel parameters. Full retains all collected driver, firewall and topology data, sysctl-net parameters and individual neighbor observations.

CSV v2 has four stable columns: section;entry;field;value. Technical section and field identifiers are language-independent; existing consumers must account for the new field names. Raw values remain available, with additional KiB/MiB/GiB values for byte counts. UI and short reports use the selected language.

Anonymize personal data modifies only an export copy. IP/MAC addresses get consistent tokens within the report. Hostnames, SSIDs, machine/boot IDs, process information and free diagnostic text are removed. Some structured hardware/network characteristics remain recognizable; review before publishing. Local data is unchanged.

Devices and findings

Known devices are grouped by usable MAC, retaining IPv4/IPv6, hostnames and all interfaces. Missing MACs do not merge different IP/interface records. Identical MACs may also occur on different network segments or cloned devices. used, confirmed and updated are represented as seconds since each event: neighbor_used_s, neighbor_confirmed_s, neighbor_updated_s; neighbor_probes counts probes. iproute2 router:null indicates a set router flag. Missing flags remain unknown and do not prove lack of router capability.

Adapter classification uses sysfs and kernel types. Virtio is virtual; insufficient evidence remains unknown. Missing models use the matching lspci record or exact PCI ID; models are never guessed from driver or firmware strings.

Counters are cumulative since their last reset, whose exact time is unknown. At 10,000 RX drops, a review note appears. This documented review threshold is not a universal hardware limit. Available ethtool drop/miss/discard counters are shown separately; they must not be added because their meanings may differ or overlap. Unsupported queries are summarized neutrally.

The default-route overview ranks IPv4/IPv6 main-table routes by metric. Policy rules, router preference, multipath and destination can influence actual route selection. Bluetooth separates kernel hardware, active service, controllers available in BlueZ and the default controller. Missing usable controllers may result from unavailable hardware or VM passthrough.

Live data and summary

RX/TX drops/s, actual sample interval, UTC timestamp and rolling byte-rate minima/maxima over at most 60 seconds supplement the live table. Pause, interface changes and counter resets start a new window. Directional utilization requires a known physical link speed; virtual/unknown links are not applicable. Raw values remain available in CSV.

System and reports include UTC scan start/end, monotonic duration, adapter counts, connected IPv4 adapters, local sockets, default gateways ranked by metric, DNS, unsupported/failed query counts and findings. These are reported observations, not a comprehensive reachability test.

The initial kernel selection is net.ipv4.ip_forward, net.ipv6.conf.all.forwarding, net.ipv4.conf.all.rp_filter, net.ipv4.tcp_syncookies, net.ipv4.tcp_congestion_control, net.ipv4.tcp_mtu_probing, net.ipv6.conf.all.disable_ipv6, net.ipv6.conf.all.accept_ra, net.mptcp.enabled and net.netfilter.nf_conntrack_max when present. Show all kernel network parameters reveals the entire collected set. Column headers remain fixed.

Show logs

Help → Show logs opens the current error log read-only. Refresh reads new messages; Close closes the viewer. Empty logs are explicitly indicated. IS107: logs/errors.log is missing, unreadable or contains invalid UTF-8. The viewer shows the error while other functions remain available. Check the file, permissions and encoding, then refresh. The next application start creates or clears the log.

The five category groups expand and collapse independently. Initially all groups are collapsed. Searching expands matching groups; clearing the search restores the previously expanded groups.

Ten interface languages and matching HTML help files are included: German, English, Spanish, French, Portuguese, simplified Chinese, Hindi, Arabic, Russian and Turkish. Choose the interface language in Edit → Settings. Arabic uses right-to-left layout.

Download languages and help

In Edit → Settings, select the download language and press Download. The catalog and HTML help come from the fixed GitHub release 1.5.4. Only missing files are added; existing custom translations are preserved. Then select the language and press Save. Internet access is needed only after clicking Download. Closing the dialog does not stop an active download.

IS108: Language/help download failed. Check your internet connection and write access to languages/ and help/, then retry. Files already saved completely are preserved.

Files are staged in ~/Downloads and deleted after installation. Other downloads are preserved. IS108 can also indicate missing write access to the download folder.

DEB

The DEB package installs ipSnoop and ipSnoop (Administrator) on the desktop. If no graphical session is detected, launchers are created at the next login. Administrator mode requests the system password. Program files: /usr/share/ipsnoop; writable data per user: ~/.local/share/ipsnoop/. Uninstallation removes tracked new program data and both launchers; pre-existing files and personal exports are preserved.
